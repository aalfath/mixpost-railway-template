# Mixpost on Railway

This repository is the source of the **Mixpost** template on Railway. It deploys [Mixpost Lite](https://github.com/inovector/mixpost), the open-source, self-hosted social media scheduler, from the official image `inovector/mixpost:v2.6.0`, pinned by digest.

## What the template deploys

| Service | Source | Data |
|---|---|---|
| Mixpost | this repo (`Dockerfile`): nginx, PHP-FPM, Horizon queue worker and the Laravel scheduler in one container | volume at `/var/www/html/storage/app` (uploaded media) |
| MySQL | Railway's MySQL | Railway volume |
| Redis | Railway's Redis (queue, cache) | Railway volume |

The wrapper only adds `railway-start.sh` and `create-admin.php`. The start script follows the image's own `start.sh`, with three changes:

1. nginx listens on `$PORT` (80 by default), on IPv4 and IPv6.
2. The first admin account gets its password from `MIXPOST_ADMIN_PASSWORD` (generated by Railway) instead of the image's fixed `changeme`. It's created only when no user exists, so a password you change in Mixpost later is never reset.
3. supervisord runs in the foreground, so Railway restarts the container when the app stops.

## Variables

| Variable | Value in the template | Notes |
|---|---|---|
| `APP_URL` | `https://${{RAILWAY_PUBLIC_DOMAIN}}` | Change it if you add a custom domain (no trailing slash) |
| `APP_KEY` | generated (Laravel `base64:` key) | Encrypts stored social account tokens. Don't change it after setup |
| `MIXPOST_ADMIN_EMAIL` | `admin@example.com` | Email of the first admin (optional) |
| `MIXPOST_ADMIN_PASSWORD` | generated | Password of the first admin. Read it in the Mixpost service's Variables tab |
| `PORT` | `80` | Port nginx listens on |
| `DB_*`, `REDIS_*` | references to the MySQL and Redis services | |

Optional settings the image reads (add them to the Mixpost service when you need them): `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_ENCRYPTION`, `MAIL_FROM_ADDRESS`, `MAIL_FROM_NAME` for email, and `MIXPOST_DISK=s3` with `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_DEFAULT_REGION`, `AWS_BUCKET` to keep media in S3. Social network API keys (X, Facebook, Mastodon and others) are set in Mixpost under **Services**.

## Updates

Changes reach deployers as Railway "update available" notices when they're merged to `main`. Each version is listed in [CHANGELOG.md](CHANGELOG.md), breaking changes first. Read it before you apply an update, and back up the MySQL database first.
